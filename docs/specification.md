# Specification

## Problem and users
Consumer-platform operators can discover many consumers but lack a trustworthy way to form a migration plan for a multi-step API revision. Static roles ignore context-dependent capability; unconstrained delegation can violate critical-consumer safeguard, residency, budget or least authority; ordinary logs cannot prove which scoped contract change existed after restart.

Contract Current serves platform operators and consumer-migration plan leads. It accepts a deterministic synthetic payment-platform OpenAPI revision, forms a multi-service migration plan, executes real policy/intelligence/persistence boundaries and returns a durable migration decision.

## Capability
Given an API revision, consumer-impact DAG and consumer services, issue a authorized migration plan only when every role has a calibrated lower bound, the migration plan satisfies policy and budgets, and analogue evidence improves but never overrides feasibility.

## Acceptance
1. Browser issues and renders a four-step contract through real Rust behavior.
2. Restricted external-only candidates are denied with no append; adding an internal specialist recovers.
3. Refresh and restart return the same contract receipt.
4. Combined evaluation exceeds ingredient-removal modes.
5. Exact-SHA quality, browser, container and semantic evidence pass.

## Contract-specific invariants
- Semantic diff precedes impact propagation; no consumer is inferred from names alone.
- Breaking changes traverse the stored producer/consumer graph transitively.
- ReCIRC calibrates a consumer-adaptive risk budget from deterministic observations.
- Cedar authorizes before RVF append; a denial cannot change the durable decision count.
- RuVector analogue evidence informs risk but cannot override compatibility or policy.
- Migration waves respect dependency order, criticality, ownership and freeze windows.
- RVF is the only service persistence layer and must reopen byte-identical evidence.
